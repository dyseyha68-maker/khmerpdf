# Calendar Admin Panel — Reference Guide

This document explains the calendar-related models in the Django admin
(`apps/pdf/admin.py` and `apps/pdf/models.py`) and how to correct or add
entries for them.

Admin URLs (require login at `/admin/`):

- Holidays: `/admin/pdf/holiday/`
- Calendar Events: `/admin/pdf/calendarevent/`

> **Note:** A `LunarDate` model previously existed here, storing a
> day-by-day Khmer lunar calendar (auto-generated by a placeholder
> `day_of_year // 30` formula, not real astronomical/traditional
> calculations) with an editable admin form. It was removed — model,
> migration, admin, management-command generation, and the "Find a Date" /
> lunar-day display on `/pdf-calendar/` are all gone. The calendar page now
> shows a plain Gregorian grid with Buddhist Era years and public holidays
> only.

---

## 1. Holiday — public holidays shown on the calendar

**Model:** `Holiday` · **Admin:** `HolidayAdmin`

Simple date-range model (`start_date`, optional `end_date` for multi-day
holidays like Pchum Ben). `name_kh` and `name_en` are editable directly from
the list view (`list_editable`). Notable admin extras:

- **Duplicate to next year** action — clones selected holidays with dates
  shifted +1 year. Useful once the current year's dates are confirmed.
- **CSV import** — a custom view at `/admin/pdf/holiday/import-csv/`
  (linked from the changelist page). Expects columns `name_en, name_kh,
  start_date, end_date, is_public, is_lunar`; dates accepted in
  `YYYY-MM-DD`, `DD/MM/YYYY`, or `MM/DD/YYYY`. Existing rows are matched and
  updated by `start_date`.
- `is_lunar` just flags whether a holiday's date is defined relative to the
  lunar calendar (e.g. Khmer New Year, Pchum Ben) — it doesn't drive any
  calculation, it's informational/filterable only.

This is the model `apps/pdf/management/commands/populate_calendar.py`
populates (11 hardcoded 2026/2027 holidays as of this writing) and the only
per-day data source the public `/pdf-calendar/` page reads from now.

## 2. CalendarEvent — optional extra events layer

**Model:** `CalendarEvent` · **Admin:** `CalendarEventAdmin`

A more general events table (`event_type`: public / religious / national /
festival / custom) that can be pinned to either a `solar_date` **or** a
lunar `lunar_month`/`lunar_day`/`lunar_year` combination — both are
optional/nullable on this model. Nothing in `calendar.html` reads from
`CalendarEvent` yet (the `events` context variable is passed to the template
but unused) — it's wired up in the backend and admin, but not surfaced on
the public page.

---

## Quick mental model

- **Want to add/edit a public holiday banner?** → `Holiday`.
- **Want to add a custom event that isn't a public holiday?** → `CalendarEvent`
  (but note it won't render on the calendar page until that template gets
  wired up to use it).
